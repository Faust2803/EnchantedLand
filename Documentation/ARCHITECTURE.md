# Архитектура EnchantedLand

## 1. Назначение

EnchantedLand — Unity-проект в жанре DND/fantasy. В репозитории предусмотрены сцены загрузки, лобби, одиночной игры и сетевой игры. Архитектура использует DI, ScriptableObject-конфигурации, отдельный слой UI и сервис сетевых сессий.

## 2. Основные каталоги

### Assets/Common

Общие системы:
- Scripts/Network — интерфейс и реализация сетевого сервиса, состояния сети и компонент сетевой трансформации.
- Scripts/UI — UiManager, базовые View/Mediator-классы, управление окнами и панелями.
- Scripts/Installers — установщики зависимостей UI и менеджеров.
- Scripts/Utils — вспомогательные компоненты, включая загрузчик сцен.
- SO — конфигурации окон и панелей, а также ScriptableObject installer.

### Assets/EnchantedLand

- Common/SO — конфигурации персонажей, монстров, заданий, путешествий и замков.
- Common/Scripts — менеджер конфигураций, данные и менеджер игрока, названия сцен.
- Game — одиночная игровая сцена и скрипты игрового модуля.
- Lobby — сцена лобби.
- Load — сцена загрузки.
- NetGame — сетевая игровая сцена и сетевые компоненты игрока.

В проекте также присутствуют Assets/Plugins/Zenject и Assets/Plugins/Demigiant/DOTween.

## 3. Сцены

| Назначение | Сцена |
|---|---|
| Загрузка | Load |
| Лобби | Lobby |
| Одиночная игра | Game |
| Сетевая игра | NetGame |

Скрипты запуска модулей:
- LoadScenesManager открывает панель загрузки.
- LobbyScenesManager открывает главную панель лобби.
- NetGameScenesManager реагирует на сетевое состояние и сетевую переменную старта матча.

**Проверка перед запуском:** в ProjectSettings/EditorBuildSettings.asset путь лобби указан как Assets/Tanks/Lobby/Lobby.unity, тогда как в дереве репозитория присутствует Assets/EnchantedLand/Lobby/Lobby.unity. Проверьте путь сцены в Build Settings и исправьте его, если он устарел.

## 4. Внедрение зависимостей (Zenject)

DI-конфигурация включает SoInstaller, ManagersInstaller, PanelsInstaller и WindowsInstaller.

SoInstaller регистрирует экземпляры ScriptableObject-конфигураций:
- WindowsConfig и PanelsConfig;
- AvatarConfig, MonsterConfig, СastleConfig, TripConfig и QuestConfig.

ConfigsManager получает конфигурации через конструктор и предоставляет их как свойства. PlayerManager также получает ConfigsManager через конструктор.

При добавлении сервиса:
1. Определите область жизни экземпляра — проект или сцена.
2. Зарегистрируйте сервис в соответствующем Installer.
3. Используйте constructor injection для обычных классов или [Inject] для Unity-компонентов.
4. Проверьте, что объект, созданный через Instantiate или сетевой механизм, проходит инъекцию. Обычный Unity Instantiate сам по себе не выполняет инъекцию Zenject.

## 5. UI

Основной координатор — Managers.UiManager.

### Окна

Используются WindowType, WindowData, BaseWindowMediator, WindowsInstaller и фабрика окон. Менеджер хранит созданные окна в словаре, текущий медиатор — в _currentWindow, очередь запросов — в очереди, предыдущие окна — в стеке.

Доступны методы открытия, принудительного открытия, закрытия текущего окна, закрытия всех окон и открытия окна с данными.

### Панели

Панели идентифицируются через PanelType, управляются базовым медиатором и создаются через фабрику панелей. Для визуальной части используются базовые View-классы.

При добавлении UI проверьте enum типа, prefab в конфигурации и регистрации фабрики/Installer.

## 6. Сеть и сессии

Основная реализация — Common.Scripts.Network.NetworkService, контракт — INetworkService, состояния — NetworkState.

### Создание сессии

CreateHostAsync(maxPlayers, mapId):
1. Переводит сервис в состояние инициализации.
2. Инициализирует Unity Services и Authentication.
3. Создаёт параметры сессии и публичное свойство mapId.
4. Добавляет Relay-конфигурацию через WithRelayNetwork().
5. Создаёт сессию, устанавливает Connected и подписывает обработчики сетевых событий.
6. Возвращает код подключения или null при ошибке.

### Подключение по коду

JoinAsync(joinCode) проверяет код, инициализирует сервисы и подключается к сессии по коду. Метод возвращает результат подключения, включая успешность и данные сессии/карты, если они доступны.

### Быстрый поиск

QuickJoinAsync(maxPlayers, mapId) использует Quick Join с тайм-аутом 10 секунд, отключает автоматическое создание новой сессии и фильтрует сессии по строковому индексу свойства карты.

### Состояния и старт матча

Состояние сообщается через StateChanged. В NetworkState предусмотрены состояния подключения, создания/поиска сессии, Connected и Failed; точный перечень следует смотреть в enum.

NetGameScenesManager содержит NetworkVariable<bool> GameStarted, доступную для чтения всем клиентам и изменяемую сервером. При значении true менеджер вызывает подготовку игроков и закрытие окон UI.

**Ограничение текущей реализации:** PlaceAllPlayers() содержит закомментированный код расстановки игроков. NetPlayer.PrepareForGame() в текущем файле не реализован. Не следует считать расстановку и подготовку игроков завершёнными без дополнительной проверки.

### Важные проверки

- У сетевого prefab должен быть NetworkObject.
- Префаб игрока должен быть зарегистрирован в списке сетевых prefab.
- Проверяйте серверные права на изменение NetworkVariable.
- Подписывайтесь на события после инициализации зависимостей и отписывайтесь при уничтожении/despawn.
- Отдельно тестируйте создание сессии, подключение по коду, Quick Join, отключение клиента и повторное подключение.

## 7. Данные игрока и конфигурации

### PlayerManager

Tanks.Common.Scripts.Player.PlayerManager хранит данные игрока в JSON-файле player_data.json по пути Application.persistentDataPath.

При отсутствии файла создаются данные по умолчанию с валютой 100. Save() сериализует данные через JsonUtility. Load() читает файл и при ошибке возвращается к данным по умолчанию.

ChangeCurrency(value) изменяет баланс, запрещает списание суммы больше текущего баланса, сохраняет изменения и вызывает OnCurrencyChanged.

Метод ValidateData() сейчас пустой; проверка диапазонов и целостности загруженных данных требует реализации.

### ScriptableObject-конфигурации

ConfigsManager агрегирует конфигурации персонажей, монстров, замков, путешествий и заданий. При изменении схемы данных следует проверить класс ScriptableObject и соответствующие asset-файлы.

## 8. Асинхронность и загрузка сцен

Проект использует UniTask. Для асинхронных методов соблюдайте единый подход к обработке исключений, отмене операций и смене состояния UI.

Перед переходом к сцене проверьте:
- сцена включена в Build Settings;
- нужные Installer и конфигурации доступны;
- нет незавершённых сетевых операций;
- события и подписки предыдущей сцены корректно очищаются.
